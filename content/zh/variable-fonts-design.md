静态字体是一个字重一个文件，变量字体把这条规则改成了一个文件里有一条连续的轴。对设计工作流的影响比听起来大：它改变了一个字重这个对象本身。

## 轴与命名实例 {#axes}
<!-- hint: 轴 | 轴是可变字体中可以调整的维度，例如 wght、wdth、opsz。命名实例只是轴上预先选好的几个位置，不是全部取值。 -->

**轴（axis）** 是可调的维度，每个轴有最小值、默认值、最大值。常见的有：

| 轴 | 含义 | 典型范围 |
| --- | --- | --- |
| `wght` | 字重 | 100–900 |
| `wdth` | 字宽 | 75–125（百分比） |
| `opsz` | 光学尺寸 | 8–144 |
| `slnt` | 倾斜 | −10–0（度） |
| `ital` | 斜体 | 0–1 |

**命名实例（named instance）** 是几个轴位置的组合，配一个名字（Regular、Bold、Display）。设计软件里的样式列表通常就是这些实例。

关键点：实例只是**预设**，不是全部。文件里没被命名成实例的位置，技术上也能取到。

## 注册轴与自定义轴 {#registered-axes}
<!-- hint: 注册轴 | 规范定义含义与标度的几根轴（wght、wdth、opsz、slnt、ital）；字体自己定义的轴不属于注册轴。 -->

<!-- source: en.wikipedia.org | Variable font | 1374197988 | CC BY-SA 4.0 | https://creativecommons.org/licenses/by-sa/4.0/ | 译自 Registered axes 一节；去掉各平台的支持时间线，只保留轴的定义与 fvar -->

上一张表的取值是**字体自己定的**：规范并不规定每根轴能取到多少。规范只定义了一组**注册轴**（registered axis）的含义与标度，让同一个 `wght` 在不同字体之间有可比性：

| 标签 | 轴 | 规范写的含义 |
| --- | --- | --- |
| `wght` | 字重 | 1 到 1000 的连续标度，400 对应 Regular |
| `wdth` | 字宽 | 正常宽度的百分比，100 为正常 |
| `opsz` | 光学尺寸 | 按字号（点）取值，供字形适配不同大小 |
| `slnt` | 倾斜 | 从直立位置起的逆时针角度；向右倾通常记作负值 |
| `ital` | 斜体 | 0 到 1，0 直立、1 斜体；与 `slnt` 是两根轴 |

`ital` 与 `slnt` 为什么分两根：“斜体”有时候只是把正体切斜（倾斜即可），有时候是一套真的另写的字形（斜体需要换字形）。两者混用会导致“我设了斜体但形状没变”。

字体可以只覆盖注册轴的一段区间，默认值也不必等于规范里的标准值 —— 看到 `wght` 默认是 300 的字体不必奇怪，那是设计取舍。除注册轴之外，字体还能定义**自定义轴**（同样是四字符标签，含义由字体自己规定），这类轴不保证跨字体通用。

这些信息都在 `fvar` 表里：每根轴一条记录（标签、最小值、默认值、最大值），命名实例也记在这里。检查器里的「变量轴」一栏读的就是它，见 [maxp 与变量轴](/docs/maxp-fvar-stat)。

## 光学尺寸是最值得理解的轴 {#opsz}

`opsz`（optical size）不是放大缩小，而是**为不同字号单独做的设计**：

- 小字号：笔画更粗、字距更开、字面框更满，否则会糊；
- 大字号：笔画更细、字距更紧、细节更多，否则会显得笨重。

传统上这靠 Text / Display 两套静态字体实现，变量字体把它变成一根连续的轴。所以 `opsz=12` 与 `opsz=72` 不只是把同一个形状缩放：笔画比例本身也变了。

CSS 里一个属性就能让它跟着字号走：

```css
h1 {
  font-optical-sizing: auto;
}
```

浏览器会根据当前的 `font-size` 自动取 `opsz`。

## 设计稿要怎么组织 {#handoff}

用变量字体时，指定字重这件事变成了三种写法，交付时要统一：

1. **命名实例**：写 SemiBold，最稳，因为实例名会跟着文件走；
2. **数值**：写 `font-weight: 600`，实现时由 CSS 匹配；
3. **轴坐标**：写 `font-variation-settings: "wght" 600`，最精确但也最不通用。

推荐：**正文与 UI 用命名实例**，只有确实需要取中间值时（比如比 SemiBold 再细一点）才用轴坐标，并在设计稿上写明原因。

## 几个容易翻车的地方 {#pitfalls}

- **中间位置不一定好看**：设计师只在几个关键点上校过形状，`wght: 437` 是自动插值的结果；
- **导出 PDF / 切图**：部分工具会把变量字体实例化成静态字形，如果实例没选好，导出的东西与屏幕上不同；
- **中文变量字体很少**：中文字形多，做连续的轴成本高，市面上的中文变量字体远比西文少；
- **`font-variation-settings` 会覆盖 `font-weight`**：两者同时出现时以轴坐标为准，容易调试不出来。

## 本站怎么记录 {#this-site}
<!-- hint: 本站的记录方式 | 本站以文件为单位记录，只取默认字重，不把轴展开成多个字款。因此可变字体在库里通常只有一档，需要在排版测试中调整轴坐标。 -->

保守：**一个文件算一个条目**，只记它的默认字重与宽度，不把轴展开成多个字款。

原因是字款在本站是收藏与档案的标识单位，而变量字体的一款不是一个离散对象。想在某根轴上试位置，是排版测试的事。
