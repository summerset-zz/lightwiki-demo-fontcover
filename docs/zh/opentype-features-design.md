很多字体里不止一套字形：大写字母有一套缩小版（小型大写），数字有等高的也有一套高低错落的，`fi` 可以连成一个……这些可选的样子由 OpenType 特性控制，每个特性有一个四个字母的标签。

## 最常见的几种 {#common}

| 效果 | 标签 | 默认 | 一眼认法 |
| --- | --- | --- | --- |
| 标准连字 | `liga` | 开 | `fi`、`fl` 连成一体 |
| 可选连字 | `dlig` | 关 | `ct`、`st` 那种花哨连接 |
| 小型大写 | `smcp` | 关 | 小号的大写字母，高度大约等于 x 高度 |
| 旧式数字 | `onum` | 关 | 数字有升有降（3、4、7、9 下探） |
| 等高数字 | `lnum` | 开 | 数字都对齐大写高度 |
| 等宽数字 | `tnum` | 关 | 每个数字占一样宽，表格里能对齐 |
| 比例数字 | `pnum` | 开 | 按字形宽度分配，正文里更自然 |
| 分数 | `frac` | 关 | `1/2` 变成真正的分数排法 |
| 上标 / 下标 | `sups` / `subs` | 关 | 脚注、化学式 |
| 样式替代 | `salt` / `ss01`–`ss20` | 关 | 同一个字母的另一种设计 |
| 本地化字形 | `locl` | 按语言 | 中日文同一码位不同写法 |

## 小型大写不是缩小的大写 {#smcp}

真正的**小型大写（small caps）** 是单独设计的一套字形：笔画粗细与大写一致，高度大约等于 x 高度。

如果字体没有这套字形，软件可以把大写缩小来凑，那是**合成**的小型大写，笔画会变细、比例会失准。设计稿上写了小型大写，实现时先确认字体到底有没有 `smcp`。

设计稿上写小型大写，落到代码有三种写法，行为并不一样：

| 写法 | 字体有 `smcp` 时 | 字体没有 `smcp` 时 |
| --- | --- | --- |
| `font-variant-caps: small-caps` | 用真字形 | 浏览器把大写缩小来凑（**合成**） |
| `font-feature-settings: "smcp"` | 用真字形 | 什么都不发生 |
| `font-variant-caps: all-small-caps` | 大小写都换成小型大写 | 同样可能合成 |

区别就在这儿：`font-variant-caps` 的意思是“我要这个效果”，允许引擎自己想办法；`font-feature-settings` 的意思是“请打开这个特性”，字体没有就照旧。前者观感更稳，后者更贴设计稿，但缺特性时会**静默失败**。

真字形靠两个特性撑着：`smcp`（小写转小型大写）与 `c2sc`（大写转小型大写）。不是所有字体都有：大写小写本来只用在正文里，所以无杠线体里尤其少见，粗体、斜体缺小型大写、只有常规体有的字体也不少。不想让浏览器合成，把这一句写上：

```css
.acronym {
  font-variant-caps: small-caps;
  font-synthesis-small-caps: none; /* 没有 smcp 就保持原样，而不是缩小大写 */
}
```

再强调一句：这些都只是**显示样式**，复制出来的仍然是原文 —— 页面上写着 “Nato”，剪贴板里还是 “NATO”。

还有一档更小的**特小型大写**（petite caps），高度约等于 x 高度：`font-variant-caps: petite-caps`，OpenType 里是 `pcap`。

## 数字的四种组合 {#figures}

数字有两个独立的维度，容易混：

| 维度 | 两种 | 用途 |
| --- | --- | --- |
| 高度 | 等高（lining）/ 旧式（oldstyle） | 等高大写高度，适合表格；旧式高低错落，适合正文 |
| 宽度 | 等宽（tabular）/ 比例（proportional） | 等宽适合数字对齐；比例适合连续文本 |

所以表格里的数字通常是等高 + 等宽，而正文里的数字通常是旧式 + 比例。字体不一定四种都有。

## 设计稿上怎么标 {#handoff}

写**标签名**最不含糊：

```
数字：tnum（表格）/ onum（正文）
标题：smcp
```

比写用小型大写更可靠，因为它能直接对应到 CSS 与字体里存在的特性。同时最好注明缺少该特性时的做法，否则实现方可能悄悄用合成的样子交差。

## 哪些会自己出现 {#defaults}

`liga` 与 `clig` 默认开，所以 `fi` 连字你通常不用管；`dlig`、`smcp`、`onum`、`tnum` 默认关，必须显式开启。

这也解释了一个常见疑问：“设计稿上 `fi` 是连着的，为什么我排出来没连？”。如果字体有 `liga` 而引擎没开，就不会连；反之如果字体没有，开也开不出来。

## 中文相关的几个 {#cjk}

| 标签 | 作用 |
| --- | --- |
| `palt` | 标点的比例宽度（让全角标点占更少的位） |
| `vert` / `vrt2` | 竖排时的替换字形 |
| `locl` | 地区字形差异（简中 / 繁中 / 日文） |
| `hwid` / `twid` / `fwid` | 半角 / 三分 / 全角宽度形式 |

中文排版里 `palt` 很实用：默认的全角标点两侧留白很大，开启后更紧凑，但也会影响对齐。

## 在本站怎么试 {#this-site}

排版预览暂时只提供字号、行高、字距、对齐这几项，OpenType 特性还没做，已列入待办。

想确认某个字体有没有某个特性：在检查器里看它的 `GSUB` / `GPOS` 能力，或者直接在预览里试。
